## ما الذي تغيّر

### `pi/mqtt_ingest.py`: "أذن" الـ Pi
يسمع `home/#`، ويحتفظ بصورة البيت في الذاكرة، ويكتب:

| إلى | ماذا |
|---|---|
| **SQLite** (`ai/data/home.db`، ذاكرة الـ AI، لا تخرج من البيت) | كل القراءات بمفاتيح العقد (`<room>/temp`، `<room>/occ`، `device/<id>`، `power/<id>`، `override/<id>` عند زر الجدار، `door/entry` عند بصمة أو رقم سري صحيح). عبر `ai.store.Recorder`: عند التغيّر الكافي + نبضة كل 15 دقيقة |
| **Firebase `/home_state`** | الغرف (حرارة، رطوبة، إضاءة، `occ`، `occ_since`، `occ_by`، `mmwave`، `pir`)، والأجهزة (`v`، `level`، `src`، `at`، `watts`)، و`power_w`. **التغيير فقط، كل ثانيتين على الأكثر** (توفير الحصة) |
| **Firebase `/nodes`** | `online`، `last_seen`، `config_version` (من `config/ack`) |
| **Firebase `/events`** | فقط ما تعرفه العقد وحدها: **زر الجدار** ("Bedroom lights turned on · Button")، و**عقدة offline / back online** |

**ويرسل** لكل عقدة جزأها من `/config` على `home/<node>/config` (retained). ويفحص `/config` كل 30 ثانية، فإذا تغيّر رقم النسخة يرسل الجديد.

**لا يتحكم بشيء:** الأوامر في `commands.py` (1c)، والقواعد والـ AI في `automation.py` (1d).

**التشغيل:**
```bash
python pi/mqtt_ingest.py            # Firebase المحلي (يملأ /config ويُنشئ حساب owner إن كانت القاعدة فارغة)
python pi/mqtt_ingest.py --memory   # بلا Firebase
python pi/mqtt_ingest.py --verbose  # كل رسالة وكل كتابة
```

### قرارات إياد (2026-10-21)

1. **الوجود:**
   - غرف الرادار (الصالة، غرفة النوم): `occ` = الرادار **أو** الـ PIR.
   - غرف الـ PIR فقط (المطبخ، الحمام): `occ` = حركة في آخر **5 دقائق** (`thresholds.pir_hold_s = 300`).
   - الثمن المعروف: الضوء قد يبقى حتى 5 دقائق بعد الخروج.
2. **`src` في `set` و`state`:** الـ Pi يرسل `{"v":1,"src":"ai"}`، والعقدة **تنسخه** في ردها. فيعرف التطبيق من شغّل الجهاز.
3. **`firebase_writer.patch_home_state()`** (جديدة): كل خدمة تكتب جزأها من `/home_state` فقط ولا تمسح أجزاء غيرها.
4. **التجربة على Firebase المحلي** (emulator)، لا الحقيقي.

### `pi/fake_nodes.py` (إصلاحات وُجدت أثناء الاختبار)
- **حلقة لا نهائية في الـ config:** العقدة كانت تعيد الاشتراك في `home/<node>/config` بعد كل config، فيعيد Mosquitto إرسال النسخة المحفوظة (retained)، فترد، وهكذا.
  - الآن تشترك **مرة واحدة**. ونفس النسخة مرة ثانية = `ack` فقط.
  - **هذا درس للجزء D (firmware):** اشترك في الـ config مرة واحدة، ولا تُعِد تطبيق نفس النسخة.
- تعيد `src` من `set` في `state`.
- الثلاجة تعمل دائماً (كانت "تنطفئ" كل 10 دقائق).

## النتائج (بوابة 1b: نجحت كلها)

التجربة: Firebase المحلي (`--only auth,database`) + `fake_nodes.py` + `mqtt_ingest.py` + التطبيق على localhost:3000.

1. **التطبيق يعرض القراءات حيّة:** الصالة 26.2°، غرفة النوم 27.6°، الحمام 26.5° + "Someone here"، الثلاجة "On · 2.0 W".
2. **غرفة PIR:** حركة في المطبخ ← `kitchen/occ = 1` في SQLite و`/home_state`.
3. **زر الجدار:** History "Bedroom lights turned on · Button · Wall button in the bedroom"، و`override/bedroom_light = 1` في SQLite.
4. **قطع الكهرباء:** إيقاف العقد فجأة ← بعد حوالي 12 ثانية يعرض التطبيق "Bedroom & bathroom node is offline" وكل الأجهزة "Not responding". وفي History "node offline · No contact (power or Wi-Fi)".
5. **SQLite:** 61 قراءة، كلها بمفاتيح العقد.
6. **تغيير `/config`** (lux للحمام، نسخة 3): `mqtt_ingest` لاحظه وأرسله، والعقد الثلاث ردّت `runs config v3`، و`/nodes/bedroom/config_version = 3`، و`lux` الحمام بدأ يصل.

**ملاحظة صغيرة:** عند كل تشغيل لـ `mqtt_ingest` تُسجَّل "node back online" للعقد المتصلة (لأنه يبدأ بحالة "غير متصل"). غير ضار.
