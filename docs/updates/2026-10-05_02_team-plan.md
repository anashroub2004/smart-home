## ما الذي تغيّر

### 1. ملف جديد: `docs/TEAM.md` — تقسيم العمل
- المشروع 4 أجزاء، **كل جزء يملك مجلداً واحداً** ولا يعدّل غيره:
  A الويب (`web/`) · B الـ Pi (`pi/`) · C الذكاء الاصطناعي (`ai/`) · D الـ ESP32 (`firmware/`).
- **الملفات المشتركة لا تُعدّل إلا بالاتفاق:** `docs/contract.md`، `docs/seed.json`، `web/lib/contract.ts`،
  `pi/firebase_writer.py`، `database.rules.json`، `docs/PROJECT_CONTEXT.md`، `CLAUDE.md`.
- **Git:** لا أحد يعمل على `main` مباشرة. كل عمل في فرع (`web/...`، `pi/...`، `ai/...`، `fw/...`، `contract/...`)
  ويدخل `main` عبر Pull Request.
- **Firebase الحقيقي:** النشر Hosting ← A فقط. `--reset` ← B فقط وبعد الإعلان. Rules ← المنسّق فقط.
- مهام كل جزء بالترتيب + رسالة بداية جاهزة لمحادثة Claude لكل جزء.

### 2. قاعدة جديدة: ملف تحديث بعد كل جلسة عمل
كل محادثة تنهي عملها بملف في `docs/updates/` بالاسم:
```
YYYY-MM-DD_NN_<وصف-قصير>.md        مثال: 2026-10-06_01_web-edit-room.md
```
يُرفع مع التعديلات في نفس الـ Pull Request، **ويُرسل أيضاً لباقي المحادثات** حتى تبقى كلها على نفس النهج.
القالب: `docs/updates/TEMPLATE.md`.

### 3. ربط الملفات
