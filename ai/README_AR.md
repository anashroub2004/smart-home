# خدمة الذكاء الاصطناعي (`ai/`)

تعمل على الـ Raspberry Pi. تتعلم عادات ساكن البيت وتتنبأ لكل جهاز: **هل سيكون شغّالاً بعد 60 دقيقة؟**
ثم لا تتصرف إلا بعد أن **توافق الحساسات**، وتراقب نتيجة قرارها، وتطفئ ما لم يعد أحد يحتاجه.

> كل الأرقام هنا محسومة باتفاق الفريق (`settings.py`). لا تُغيَّر إلا بعد الاتفاق وتحديث `docs/PROJECT_CONTEXT.md`.

## التثبيت والتجربة (بدون عتاد)

```bash
pip install -r ai/requirements.txt
python -m ai.run demo        # 10 أسابيع محاكاة ← تدريب ← خطة الساعة القادمة
python -m ai.run devices     # الأجهزة، نوعها، عتبتها، ما يستخدمه كل نموذج
python -m ai.run report      # تقرير التدريب الكامل (الدقة، المعايرة، أهمية العوامل، تغيّر العادات)
python -m ai.run evaluate    # تجارب التقرير ← ai/models/evaluation.md
python -m unittest discover -s ai/tests -t .     # الاختبارات
```

المحاكي يشغّل هذا الـ AI تلقائياً: `python pi/sim_house.py --fast`. في أول تشغيل يولّد تاريخاً محاكىً
(10 أسابيع) ويدرّب (~20 ثانية)، والنماذج في `ai/models/sim/`.

## سياسة القرار

```
① توقّع (كل 15 دقيقة)        p = احتمال أن يكون الجهاز شغّالاً بعد 60 دقيقة
② بوابة الحساسات (لحظة التنفيذ)   الضوء: وجود + ظلام · الحراري: حرارة فوق الحد + شخص في البيت · غيره: وجود
③ حارس الهدر (بعد التشغيل)      لم يأتِ أحد حتى الموعد + 10 دقائق ← يطفئه، يسجّل "Prediction missed"، ويتعلم
④ إطفاء ذكي                    رادار و PIR فارغان معاً: الضوء 5 دقائق، غيره 10
```

| الاحتمال | الجهاز | القرار |
|---|---|---|
| ≥ العتبة | مطفأ | `schedule_on` — نية تشغيل، تُنفَّذ إذا وافقت البوابة |
| ≥ العتبة | شغّال | `keep_on` — يؤخّر الإطفاء الذكي (×2) |
| العتبة − 0.20 حتى العتبة | مطفأ | `suggest_on` — فقط إذا الحساسات توافق الآن |
| ≤ 0.20 | شغّال | `suggest_off` (والإطفاء الذكي يصبح أسرع ×0.5) |
| تحكم يدوي خلال ساعتين (أو حتى تغادر الغرفة) | — | `paused_by_override` |
| إيقاف من التطبيق | — | `paused_by_user` |

- **الأضواء لا تُشغَّل مسبقاً أبداً:** الخطة تعني "شغّلها فور دخولك إذا كان الضوء منخفضاً".
- **التبريد المسبق:** 15 دقيقة فقط، وبشرط وجود شخص في البيت.
- **Hysteresis:** بعد أن يقرر التشغيل يبقى عليه حتى ينزل الاحتمال تحت (العتبة − 0.10).

### العتبات حسب الاستهلاك

`act = ai_act_at − 0.15 + 0.085 × log10(1 + watts)` بين 0.60 و 0.97:

| الجهاز | الواط | يُنفَّذ عند | يُقترح عند |
|---|---|---|---|
| ضوء LED | 1.2 | 0.68 | 0.50 |
| مروحة المجسّم | 2.4 | 0.69 | 0.50 |
| تلفاز | 100 | 0.82 | 0.62 |
| مدفأة | 800 | 0.90 | 0.70 |
| مكيف | 1500 | 0.92 | 0.72 |

- **العتبة المتكيّفة:** كل رفض لاقتراح يرفعها 0.03 لهذا الجهاز في هذه الساعتين، وكل قبول يخفضها 0.02 (بين −0.10 و +0.15).
- **تغيّر العادات:** العتبة +0.10 مؤقتاً.
- **تعديل يدوي لجهاز:** `"ai": {"act": 0.85}` في إعداداته.

## التدريب (كل ليلة 03:00)

1. آخر **8 أسابيع** فقط. أيام Away مستبعدة. فترات `ai_miss` تُحسب "مطفأ" حتى لا يتعلم من أخطائه.
2. اختبار على **آخر 14 يوماً بالترتيب الزمني** (أبداً ليس عشوائياً).
3. أوزان: زمنية (نصف عمر 14 يوماً) × تكلفة الطاقة (الخطأ في جهاز ثقيل يُعاقَب أكثر).
4. المقاييس:
   - F1، Precision، Recall.
   - توقيت التغيير بالضبط وضمن ±15 دقيقة.
   - خط الأساس "مثل أمس": يجب أن يتفوق عليه النموذج.
   - المعايرة (هل 80% تعني فعلاً 80%؟) و Brier.
5. أهمية العوامل (permutation importance) حسب المجموعات: الوقت، العادة، الوجود، الحرارة، الضوء، أجهزة أخرى.
6. كشف تغيّر العادات: إذا هبط F1 آخر 7 أيام 0.15 عن الأسبوع الذي قبله ← `relearning`.
7. النموذج النهائي على النافذة كلها ← `ai/models/<device>.joblib`.
8. أيضاً:
   - نموذج الوجود `presence.joblib`.
   - خطوط أساس الطاقة `baselines.json`.
   - التقرير `report.json`.

**الصدق في الأرقام:** `data_source` = `simulated` / `mixed` / `real` يُكتب في التقرير وفي `/ai_insights`.

## كشف أعطال الطاقة

يتعلم الاستهلاك الطبيعي لكل جهاز (لكل مستوى سرعة) بالوسيط و MAD، ثم ينبّه في هذه الحالات:

| الحالة | الشرط | مثال |
|---|---|---|
| `high` | يسحب ≥ 1.5× المعتاد وفوق الوسيط + 4×MAD | محرك عالق |
| `dead` | شغّال لكن يسحب أقل من 20% من المعتاد | مصباح محروق |
| `standby` | مطفأ ويسحب > 0.3 W | ريليه عالق |

- يجب أن يستمر الشرط 3 دقائق، والتنبيه نفسه لا يتكرر قبل 6 ساعات.
- كل ليلة: إذا ارتفع الاستهلاك المعتاد 25% خلال 4 أسابيع تظهر حالة `wear` (تآكل).
- تجربة: `python pi/sim_house.py --fast --fault bedroom_fan`

## سجل الهدر

يُحسب كل ثانية: جهاز يعمل والغرفة **فارغة مؤكدة** ← الواط × الزمن، مع السبب:
- `forgotten`
- `rule_delay`
- `ai`
- `standby`

← `/energy_waste/{day}`، والملخص (ما وفّره الـ AI − ما هدره) في `/ai_insights/energy`.

## الربط على الـ Pi (للجزء B)

```python
from ai.runtime import AIRuntime
from ai.dispatch import FirebaseSink, MqttExecutor
rt = AIRuntime(config, ai.store.connect(), FirebaseSink(writer))
rt.bootstrap_if_needed()            # يولّد تاريخاً محاكىً فقط إذا كانت قاعدة البيانات فارغة تماماً
# كل 15 دقيقة:  rt.plan(house)
# كل 5 ثوانٍ:   for a in rt.tick(house, dt=dt): MqttExecutor(client, config).execute(a)  + سجّل الحدث (source "ai")
# عند تحكم يدوي: rt.on_manual(device)      · عند رد على اقتراح: rt.on_answer(id, suggestion, accepted)
# كل ليلة 03:00: rt.retrain()
```

`house` = الغرف (occ, mmwave, pir, temp, lux) + الأجهزة (v, level, watts, src) + `paused` + `door_entry_at` + `away`.
المرجع الكامل للربط: `pi/sim_house.py` (`start_ai`, `run_ai`, `ai_tick`).

مفاتيح SQLite: آخر قسم في `docs/contract.md`.
