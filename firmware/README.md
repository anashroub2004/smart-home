# firmware/ — كود الـ ESP32 (لاحقاً)

سنكتب هنا 3 مشاريع PlatformIO عند وصول القطع:

```
firmware/
  room_node/     # الصالة+المطبخ  و  غرفة النوم+الحمام (نفس الكود، الإعدادات من /config)
  door_node/     # البصمة + لوحة الأرقام + السيرفو
  common/        # MQTT + WiFi + LWT + استقبال config
```

## خريطة الأطراف (من خارطة الطريق)

### عقدة الغرف (living / bedroom)

| الطرف | الوظيفة |
|---|---|
| GPIO21 / 22 | I2C — SHT31 (0x44)، BH1750 (0x23)، INA226 (0x40/0x41/0x42) |
| GPIO16 / 17 | UART2 — رادار C1001 |
| GPIO34 / 35 | PIR (إدخال فقط) |
| GPIO25 | MOSFET المروحة (PWM) |
| GPIO26 | ريليه الإضاءة |
| GPIO32 / 33 | أزرار التحكم اليدوي |
| GPIO27 / 14 | (غرفة النوم فقط) MOSFET الغسالة + زرها |

### عقدة الباب

| الطرف | الوظيفة |
|---|---|
| GPIO16 / 17 | R503 بصمة (UART) ، GPIO4 = wakeup |
| 13, 14, 27, 26 | صفوف لوحة الأرقام 4×4 |
| 25, 33, 32, 23 | أعمدة لوحة الأرقام |
| GPIO18 | سيرفو MG996R (تغذية 5V منفصلة!) |
| GPIO19 / 5 / 21 | بازر / LED / زر الخروج |

## العقد مع الـ Pi

راجع `docs/contract.md` — قسم MQTT. القاعدة: العقدة لا تعرف Firebase إطلاقاً، فقط MQTT.

## الأجهزة من الإعدادات (لا أجهزة ثابتة في الكود)

كل عقدة تستقبل جزءها من `/config` عبر `home/<node>/config` (retained) وتبني أجهزتها منه:
- `hw.out = relay | pwm | ir | servo` → نوع الخرج على `hw.pin`
- `hw.button` → زر حائط يعمل حتى بدون إنترنت
- `hw.ina` → INA226 تُقرأ دورياً وتُرسل على `home/<room>/<device>/power`
- أجهزة `caps.power = "read"` (مراقبة فقط) ليس لها خرج — فقط INA226.

إضافة جهاز من التطبيق **لا تحتاج إعادة برمجة العقدة**. التفاصيل في `docs/ADDING_DEVICES.md`.
